# 开发辅导手册

> 目标：让你不仅能“把项目跑起来”，还能在答辩时讲清楚每一层在做什么，并且能自己加功能。  
> 建议顺序：先按第 1—4 步跑通，再按第 5—7 步读代码，最后按第 8 步做答辩准备。

## 一、先认识这个项目

这是一个**传统 Java EE 分层项目**，不是 Spring Boot：

```text
浏览器
  ↓ HTTP + Session
Tomcat 11
  ↓
Filter（编码 / 登录 / 侧边栏待办）
  ↓
Servlet（接收参数、调 Service、转发 JSP）
  ↓
Service（业务规则、状态机、事务）
  ↓
DAO（JDBC + DbUtils + PreparedStatement）
  ↓
Druid 连接池
  ↓
MySQL 8
```

你在 IDEA 里看到的所有代码，基本都能归到下面五层：

| 层 | 包 | 你要回答的问题 |
| --- | --- | --- |
| 实体 | `entity` | 数据库一行数据对应哪个 Java 对象？ |
| 数据访问 | `dao` | SQL 写在哪里？结果怎么变成对象？ |
| 业务 | `service` | 状态能不能改？要不要事务？失败怎么提示？ |
| 控制 | `servlet` | 接收什么参数？调用哪个 Service？跳到哪个 JSP？ |
| 视图 | `WEB-INF/views` | 数据怎么展示？表单提交到哪里？ |

## 三、第 1 步：准备数据库

### 方式 A：让项目自动初始化（推荐）

只要 MySQL 服务在运行，第一次启动项目时 `AppContextListener` 会检测 `campus_trade.t_user` 是否存在；不存在就自动执行：

```text

```

不需要手动建库。

双击：

```bat

```

它会执行：


初始化完成后，用 IDEA 的 Database 工具或命令行检查：

```sql
USE campus_trade;
SELECT COUNT(*) FROM t_user;      -- 7
SELECT COUNT(*) FROM t_product;   -- 14
SELECT COUNT(*) FROM t_order;     -- 7
SELECT COUNT(*) FROM t_report;    -- 5
```

> 本机 MySQL：`localhost:3306`，`root / 123456`。如果密码不同，改 `src/main/resources/db.properties`。

## 五、第 3 步：读懂一条完整请求（以登录为例）

### 1. 浏览器提交

`login.jsp`：

```html
<form method="post" action="${ctx}/login">
    <input name="username">
    <input name="password">
</form>
```

### 2. Filter 处理编码

`EncodingFilter`：

```java
request.setCharacterEncoding("UTF-8");
response.setCharacterEncoding("UTF-8");
chain.doFilter(request, response);
```

> 注意：这里不能写 `response.setContentType("text/html")`，否则 CSS/JS 也会被当成 HTML，页面会失去样式。项目已经修复这个问题。

### 3. Servlet 接收

`LoginServlet.doPost()`：

```java
String username = param(req, "username");
String password = req.getParameter("password");
User user = authService.loginAdmin(username, password);
```

### 4. Service 校验

`AuthService.loginAdmin()`：

```java
User user = userDao.findByUsername(username);
if (user == null || !PasswordUtil.matches(password, user.getPassword())) {
    throw new BizException("账号或密码错误");
}
if (!"ADMIN".equals(user.getRole())) {
    throw new BizException("该账号不是管理员");
}
```

### 5. DAO 查询

`UserDao.findByUsername()`：

```java
String sql = "SELECT ... FROM t_user WHERE username = ?";
return qr.query(sql, new BeanHandler<>(User.class), username);
```

`?` 是 PreparedStatement 占位符，用户输入不会拼进 SQL。

### 6. 写入 Session 并跳转

```java
HttpSession oldSession = req.getSession(false);
if (oldSession != null) oldSession.invalidate();
HttpSession session = req.getSession(true);
session.setAttribute("loginUser", user);
resp.sendRedirect(req.getContextPath() + "/admin/dashboard");
```

### 7. 进入后台

`AuthFilter` 拦截 `/admin/*`：

```java
User loginUser = session == null ? null : (User) session.getAttribute("loginUser");
if (loginUser == null) {
    resp.sendRedirect(req.getContextPath() + "/login?redirect=...");
    return;
}
```

### 8. JSP 渲染

`DashboardServlet` 调 `DashboardService.load()`，把 `DashboardData` 放到 request：

```java
req.setAttribute("data", data);
forward(req, resp, "dashboard.jsp");
```

`dashboard.jsp` 用 JSTL 输出：

```jsp
<c:forEach items="${data.trend}" var="point">
    <div class="trend-bar" style="height: ${point.percent}%"></div>
</c:forEach>
```

## 六、第 4 步：每一层怎么写

### 6.1 Entity

以 `Product` 为例，字段与表列对应，额外加“展示用 getter”：

```java
public String getStatusLabel() {
    return switch (status) {
        case "PENDING" -> "待审核";
        case "APPROVED" -> "已通过";
        ...
    };
}

public String getStatusClass() {
    return status.toLowerCase().replace('_', '-');
}
```

JSP 中就可以写 `${product.statusLabel}`、`class="badge ${product.statusClass}"`，避免在页面里写大量 `c:choose`。

### 6.2 DAO

DAO 只做三件事：写 SQL、传参数、映射结果。

```java
public Product findById(long id) throws Exception {
    return qr.query(BASE_SELECT + " WHERE p.id = ?",
            new BeanHandler<>(Product.class), id);
}
```

分页查询：

```java
sql.append(" ORDER BY p.create_time DESC LIMIT ? OFFSET ?");
params.add(limit);
params.add(offset);
```

> 列名用 `AS camelCase` 映射到 Java 属性，例如 `p.seller_id AS sellerId`。

### 6.3 Service

Service 负责业务规则。以商品审核为例：

```java
Product product = findById(productId);
if (!product.isPending()) {
    throw new BizException("该商品当前状态不能重复审核");
}
DbUtil.inTransaction(connection -> {
    productDao.audit(connection, productId, decision, reason, operator.getId());
    auditLogDao.insert(connection, buildLog(...));
    return null;
});
```

为什么用事务？因为“改商品状态”和“写审核日志”必须一起成功，不能只成功一半。

### 6.4 Servlet

Servlet 不写业务，只做参数和跳转：

```java
long id = requireId(req);
productService.audit(id, decision, reason, currentUser(req));
flashSuccess(req, "商品审核完成");
redirect(req, resp, "/admin/products?action=detail&id=" + id);
```

异常统一交给 `BaseServlet.handleError()`，把 `BizException` 转成用户可读提示。

### 6.5 JSP

页面放在 `WEB-INF/views` 下，浏览器不能直接访问，只能由 Servlet forward。

一个列表页通常包含：

```jsp
<%@ include file="/WEB-INF/views/common/header.jsp" %>
<!-- 筛选卡 -->
<!-- 表格 -->
<%@ include file="/WEB-INF/views/common/pagination.jsp" %>
<%@ include file="/WEB-INF/views/common/footer.jsp" %>
```

详情页通常是“左信息 + 右操作”：

```jsp
<div class="detail-layout">
    <div class="detail-main">...</div>
    <aside class="detail-side">
        <section class="card sticky-card">操作表单</section>
    </aside>
</div>
```

## 七、第 5 步：按模块读代码

建议按下面顺序读，每个模块都按“Entity → DAO → Service → Servlet → JSP”走一遍。

### 7.1 商品审核

| 文件 | 重点 |
| --- | --- |
| `Product.java` | 状态、成色、价格、关联卖家/分类 |
| `ProductDao.java` | 动态筛选、分页、审核 SQL |
| `ProductService.java` | 重复审核校验、批量审核、事务、日志 |
| `ProductServlet.java` | `action=audit/batch/status/delete` |
| `product/list.jsp` | 筛选、表格、批量勾选 |
| `product/detail.jsp` | 审核表单、驳回校验、审核记录 |

### 7.2 订单管理

| 文件 | 重点 |
| --- | --- |
| `Order.java` | 状态、各节点时间、买家/卖家 |
| `OrderDao.java` | 多表连接、状态时间戳、趋势统计 |
| `OrderService.java` | `nextStatuses()` 状态机、事务 |
| `OrderServlet.java` | 列表、详情、导出 |
| `order/detail.jsp` | 时间线、状态流转表单 |

重点理解 `nextStatuses()`：

```java
case "SHIPPED" -> {
    options.add(new StatusOption("COMPLETED", "确认交易完成"));
    options.add(new StatusOption("REFUNDING", "转入退款处理"));
}
```

前端只展示允许的目标状态，Service 再校验一次，防止改参数越权。

### 7.3 举报处理

| 文件 | 重点 |
| --- | --- |
| `Report.java` | 多态对象、原因、处理动作 |
| `ReportDao.java` | 关联举报人/处理人/对象标题 |
| `ReportService.java` | `resolveProductId()`、`resolveUserId()`、联动处罚、事务 |
| `ReportServlet.java` | `action=handle/process` |
| `report/detail.jsp` | 对象快照、处罚下拉框、处理说明 |

`ReportService.handle()` 是项目最复杂的业务，建议重点讲：

```java
DbUtil.inTransaction(connection -> {
    reportDao.handle(connection, reportId, decision, operator.getId(), result, action);
    auditLogDao.insert(connection, ...);
    if ("OFF_SHELF".equals(action)) { ... }
    if ("BAN_USER".equals(action)) { ... }
    if ("WARN".equals(action)) { ... }
    return null;
});
```

### 7.4 用户管理

| 文件 | 重点 |
| --- | --- |
| `UserDao.java` | 分页、详情统计、封禁/改密/扣分 |
| `UserService.java` | 不能封自己/管理员、重置密码 |
| `UserServlet.java` | 列表、详情、状态、重置密码 |
| `user/detail.jsp` | 资料卡、统计卡、商品/订单/举报记录 |

### 7.5 分类与日志

- `CategoryService.save()`：名称非空、长度、重复、尖括号校验。
- `CategoryService.delete()`：分类下有商品时拒绝删除。
- `AuditLogService.page()`：按业务类型、动作、关键词筛选。
- `AuditLog` 的 `getActionLabel()` 把英文动作转成中文。

## 八、第 6 步：自己加一个功能（以“公告管理”为例）

答辩时老师常问“如果让你加一个功能，你会怎么加？”你可以按这个套路回答。

### 1. 建表

```sql
CREATE TABLE t_notice (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(120) NOT NULL,
    content TEXT,
    status VARCHAR(20) NOT NULL DEFAULT 'DRAFT',
    create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

### 2. Entity

`Notice.java`：`id/title/content/status/createTime`，加 `getStatusLabel()`。

### 3. DAO

`NoticeDao.java`：

```java
public List<Notice> findPage(int offset, int limit) throws Exception
public long count() throws Exception
public int insert(Connection conn, Notice notice) throws Exception
```

### 4. Service

`NoticeService.java`：发布、下线、删除，写 `t_audit_log`。

### 5. Servlet

`NoticeServlet` 映射 `/admin/notices`，`action=list/save/delete`。

### 6. JSP

- `WEB-INF/views/notice/list.jsp`
- 在 `header.jsp` 侧边栏加一个导航项。
- 在 `AuditLog.getActionLabel()` 里加 `PUBLISH/DELETE` 的中文。

### 7. 测试

- 列表能打开
- 新增后能查到
- 删除有确认
- 审核日志有记录
- 分页正常

## 九、第 7 步：调试与常见错误

### 9.1 IDEA 断点调试

推荐两种方式：

**方式 A：脚本启动 + Remote 调试**

1. 在 IDEA 新建 `Remote JVM Debug`，端口 `8000`。
2. 用调试参数启动 Tomcat（在 `catalina-local.bat` 前设置）：
   ```bat
   set JPDA_ADDRESS=8000
   set JPDA_TRANSPORT=dt_socket
   call .tomcat\bin\catalina-local.bat jpda run
   ```
3. IDEA 点击 Debug 连接，断点会生效。

**方式 B：IDEA Tomcat 配置**

1. `Run → Edit Configurations → + → Tomcat Server → Local`。
2. Application server 选择 `D:\apache-tomcat-11.0.22`。
3. Deployment 添加 `campus-trade-admin:war exploded`，Context 填 `/campus-trade-admin`。
4. 注意：如果 IDEA 使用全局 Tomcat 配置，可能再次遇到 `Struts2Demo` 启动失败；此时改用脚本方式更稳。

### 9.2 看日志

- Tomcat 控制台：`scripts\start-server.bat` 的窗口。
- 文件日志：`.tomcat\logs\catalina.2026-10-31.log`。
- JSP 编译错误：搜索 `org.apache.jasper`。
- 数据库错误：搜索 `SQLException`、`Access denied`。

### 9.3 常见错误对照表

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 404 | 访问地址少了上下文 | 用 `/campus-trade-admin/` |
| 500 + `Access denied` | 数据库密码不对 | 改 `db.properties` 或设 `CAMPUS_DB_PASSWORD` |
| 500 + `Table doesn't exist` | 数据库没初始化 | 运行 `scripts\init-db.bat` 或重启触发自动初始化 |
| 页面无样式 | CSS MIME 错误 / 缓存 | 强制刷新，检查 `Content-Type: text/css` |
| 中文乱码 | 编码不一致 | 检查 UTF-8、`URIEncoding="UTF-8"`、`-Dfile.encoding=UTF-8` |
| `JRE_HOME ... not defined` | 全局环境变量/原脚本硬编码 | 用 `scripts\start-server.bat` |
| `Struts2Demo` 启动失败 | 全局 Tomcat 残留 Context | 用项目 `.tomcat` 独立实例 |
| 端口 8080 被占用 | 另一个 Tomcat/程序 | 改端口或停止占用程序 |
| JSP 报 `jakarta.tags.core` 找不到 | 缺少 JSTL 3 | 确认 `pom.xml` 有 JSTL 依赖，WAR 的 `WEB-INF/lib` 有 JSTL |
| 登录后立即跳回登录 | Session 丢失/Cookie 被禁 | 检查浏览器 Cookie，确认 `JSESSIONID` |
